tonto · a one-hour introduction

tonto from scratch

tonto is OntoUML written as text. You write a conceptual model the way you write code, and an editor that knows the Unified Foundational Ontology (UFO) checks it as you type: it tells you what is wrong, why, and how to repair it. This page follows the demonstration: the agenda, the model we build one step at a time, and where to go next.

  • Editor Visual Studio Code 1.95 or later
  • Extension tonto, installed from a VSIX file
  • Nothing else no Node.js, no command line

Severity is a claim about certainty. An error means no instance could satisfy the model. A warning means it is almost certainly not what you meant. A hint means the model could say more, and need not. Most diagnostics come with repairs. Some decide nothing, such as fixing a typo or swapping bounds written the wrong way round; tonto check --fix applies those, and the editor offers them as quick fixes. The others are choices between readings of the model, and those are left to you.

From the model to OWL

Run tonto: Export to gUFO…. The command checks the ontology with everything it imports and asks once for the namespace. It then saves that namespace in the ontology’s header, so the next export does not ask again, writes the Turtle beside the ontology file and opens it. With several ontologies in the workspace, it lists them, all checked, and Enter exports each beside its own file. The role becomes a class that exists only with an enrollment behind it. studiesAt records the relator it is derived from, and a property chain says the same thing to a reasoner: a student studies at a university when an enrollment mediates both. Graduate is defined by what it is derived from: a person who, as a student, graduated. A role cannot be defined by its relator that way, since an enrollment that has ended stays in the data and would go on making a former student a student; a historical role’s members grow exactly as the events it is derived from do. Working with an agent

Run tonto: Set Up Codex and Claude in Workspace. It adds project instructions and configures a local MCP server, the Model Context Protocol server that lets an agent call tools, so Codex or Claude Code can read the language guide and check a model. They also get the same repairs you use. An agent that writes tonto is checked by the validator you just watched, so a model it proposes comes with the diagnostics it would raise. The extension ships its own runtime, so there is nothing else to install.

Words you will hear

The UFO vocabulary behind the steps above, in the order it appears.

kind
A type that supplies the identity of its instances, such as Person. An instance is of exactly one kind for as long as it exists.
phase
A stage an instance passes through because of a change in the instance itself: Child, Adult.
generalization set
A statement about several specializations at once. disjoint: nothing is in two of them. complete: everything is in one of them. Written genset.
role
A type an instance has only while it stands in a relationship: someone is a Student while enrolled.
relator
The relationship made into a thing, such as an Enrollment. It is what founds a role, and where properties such as a start date belong.
@mediation
The link from a relator to what it binds. The relator cannot exist without them.
@material
A relation people name, such as studiesAt, true because a relator holds. derivedFrom says which relator.
event
Something that happened, such as a Graduation. Once over, nothing about it changes.
historical role
A role that holds forever once it holds, because of an event: a Graduate never stops being one. derivedFrom names the participation, creation or termination it is derived from.
@participation
The link from something that takes part in an event to the event.
[1..*] (const) (addOnly)
Multiplicity says how many are linked at each end. const says the link cannot change; addOnly says links may be added and never removed.
  • Error
    The model contradicts itself: nothing could be an instance of it as written.
  • Warning
    Defensible, but almost certainly not what you meant.
  • Information
    Anti-patterns known to correlate with modeling errors. Off unless you turn them on.
  • Hint
    The model could say more, and need not. A faint underline, kept out of the Problems panel.

Try it yourself

While tonto is in preview it is distributed as a VSIX file. In VS Code, open the Extensions view, choose Install from VSIX… from its … menu, and select the file. The Get Started walkthrough opens by itself. Everything the extension does is in the Command Palette under tonto:.

CommandWhat it does
Get StartedReopens the walkthrough: a first ontology, language guide, validation, export, agents.
New Ontology…Asks for an ontology name and writes a one-file ontology that validates; in a folder not yet set up for coding agents, sets them up too.
New Package…Adds a package to one of the workspace’s ontologies: its package file and its entry in the ontology file, splitting a one-file ontology first.
Open Language GuideEvery stereotype, nature and association on one page, generated from the tables the validator uses.
Insert Modeling Pattern…Inserts a validated pattern at the cursor, with linked names.
Export to gUFO…Checks the workspace’s ontologies and writes each as gUFO-aligned Turtle beside its ontology file.
Export to gUFO with Snapshot Layer…Also writes what holds at a single instant, and SHACL shapes to check a graph of current state against.
Fetch Ontology DependenciesRetrieves the ontologies the workspace imports by location, into its .tonto cache. Checking itself never goes to the network.
Refresh Ontology DependenciesRetrieves them again, replacing the cached copies.
