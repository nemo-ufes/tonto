server, and fresh disposable workspaces. Claude selected `claude-opus-5-5`;
Copilot selected `claude-sonnet-5.5`. Codex did not report a model identifier
in its JSONL stream. A pass requires the expected model
structure, no tonto diagnostics, and a successful tonto validation that starts
after the saved edit completes.

In both Copilot workspace runs, the final model passed the independent tonto
check with no diagnostics. Copilot started `tonto_validate` in parallel with
the write to `sales.tonto`, so its tool result does not establish that it
checked the new model. The extension guidance now explicitly requires waiting
for the edit to finish before validation. The second run still reproduced the
same order. `copilot instruction list` confirmed the fixture's `AGENTS.md` was
discovered.

VS Code used tonto extension `0.1.61+20261017095139` and Copilot Chat's Auto
model selection. An initial draft and repair run passed, but their fixture
contained `.mcp.json`; those calls used the MCP server and do not test the
extension's native language-model tools. I moved that configuration out of
the workspace and reloaded VS Code before the native-tool runs:

| VS Code case | Auto-selected model | Native tonto tools | Independent tonto check |
|---|---|---|---|
| Draft role and relator | Claude Sonnet 5.5 | Guide, patterns, validate after edit | No diagnostics |
| Repair parthood diamond | GPT-6 Luna | Validate, diff, format after edit | No diagnostics |
| Split workspace | GPT-6 Luna | Guide, patterns, format, diff, validate after edit | No diagnostics |

The draft agent corrected two warnings from its first edit. The split-workspace
agent edited the package file and validated the saved ontology. The repair
agent produced the intended diamond and multiplicities. These editor runs
shared one trusted disposable VS Code root, so the repair case also saw other
completed fixtures; it verifies native tool availability and the target repair,
not independent model quality. In its draft comparison, `tonto_diff` reported
an ontology-name clash that did not appear when validating the saved file.
That was a defect: text of a saved file was checked beside the file rather
than in its place. It is fixed; such text now stands in for the file.
Use a separate prepared VS Code workspace per case for an isolated repeat.

The new `vscode` fixture mode omits `.mcp.json`, so future editor runs can
exercise the extension's own tools without the MCP server masking them.

These runs predate two changes to the runner: validation must follow the last
edit, not any edit, and Claude runs include the validation hook and load
project settings only. After them, Claude Code 2.1.302 passed the repair and
split-workspace cases again, with the hook running on each edit.
